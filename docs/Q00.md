# Q00 — Contrat des deux interactions retenues

Types validés par l’utilisateur : appariement et mise en ordre. Périmètre initial :
2 à 8 éléments distincts, correspondance bijective, réponse partielle possible,
aucun crédit partiel. Exact complet = tous les points ; incorrect, incomplet ou vide =
zéro. Les deux types restent des examens blancs chronométrés côté serveur.

Chaque réponse est une association ligne/option. Pour l’ordre, les lignes sont les
positions. Surveys conserve les associations comme choix multiples natifs ; le
nouvel attribut d’interaction détermine le rendu et les contraintes de bijection.
Le barème exact, la durée, les tentatives, la correction finale et les résultats
par thème du pont TM sont réutilisés. Aucun modèle de score parallèle et aucun
contournement de la publication native.

Les choix représentent toutes les associations possibles ; seul le serveur connaît
la solution. Identifiants aléatoires et affichage alphabétique des options : aucun
indice d’ordre correct dans les clés. Les données transmises avant fin ne contiennent
ni indicateur correct, ni points par association, ni solution. Après fin, la correction
native affiche les associations retenues et attendues avec l’explication.

L’auteur configure les appariements par lignes « gauche | droite », et l’ordre par
une liste dans l’ordre correct. La publication vérifie matrice complète, unicité,
labels distincts et solution bijective, puis applique aussi tous les contrôles TM.
Le gel natif empêche toute modification publiée ; les révisions conservent V1.
Les QCU/QCM existants ont un attribut d’interaction vide et gardent leur comportement.
La banque partagée et les autres types restent hors de ce lot.
